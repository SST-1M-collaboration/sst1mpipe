Processing the data with the ctapipe tools

The raw data (R0) of the SST-1M telescopes are processed with two ctapipe tools, run one after the other on each run (raw data file SST1M<tel>_<date>_<run>.fits.fz of a telescope):

  1. sst1mpipe-monitoring: monitoring data of the run (pointing and statistics of the pedestal events), see 1. Monitoring of the run: sst1mpipe-monitoring

  2. sst1mpipe-process: calibration and DL1 (and DL2 geometry) of the events of the run, with the monitoring data of the run, see 2. Processing of the run: sst1mpipe-process

The DL1 files of the runs can then be merged, see 3. Merging.

SST1M1_20260120_1179.fits.fz ──► sst1mpipe-monitoring ──► SST1M1_20260120_1179.monitoring.h5
          │                                                          │
          └──────────────────► sst1mpipe-process ◄───────────────────┘
                                      │
                                      ▼
                        SST1M1_20260120_1179_W1.dl1.h5  ──►  ctapipe-merge

The command line tools sst1mpipe-monitoring and sst1mpipe-process are installed with sst1mpipe (see Introduction).

Configuration

All the tools take a configuration file (--config, JSON or YAML), and every setting can also be given on the command line, e.g. --WaveformStatisticsCalculator.PedestalWaveformAggregator.SizeChunking.chunk_size=50. --help lists the main options and --help-all all the settings. The configuration used is stored in the provenance log of the tool (<tool>.provenance.log, --provenance-log).

The configuration files of sst1mpipe are in sst1mpipe/resources/config:

Each section of a file configures a component (a ctapipe class) by its name. The settings of a telescope component can be given per telescope, as a list of rules: ["type", "*", value] for all the telescopes, ["id", 21, value] for telescope 21. When several rules match a telescope, the last one wins. A plain value applies to all the telescopes.

1. Monitoring of the run: sst1mpipe-monitoring

sst1mpipe-monitoring \
    --input SST1M1_20260120_1179.fits.fz \
    --output SST1M1_20260120_1179.monitoring.h5 \
    --config sst1mpipe/resources/config/sst1mpipe_monitoring_config.json

The raw data file is read twice (the images of the pedestal events are calibrated as the events by sst1mpipe-process, with the statistics of the ADC samples), and the monitoring file contains the pointing of the telescope, the statistics of the ADC samples of the pedestal events (baseline and noise, for the voltage drop correction and the dead pixels) and the statistics of their images (NSB noise, for the NSBImageCleaner), in rolling chunks of the last pedestal events. What the tool does, its settings and the content of the monitoring file are described in Monitoring of a run: sst1mpipe-monitoring.

2. Processing of the run: sst1mpipe-process

sst1mpipe-process \
    --input SST1M1_20260120_1179.fits.fz \
    --output SST1M1_20260120_1179.dl1.h5 \
    --config sst1mpipe/resources/config/sst1mpipe_data_config.json \
    --monitoring-source SST1MMonitoringSource \
    --SST1MMonitoringSource.input_files SST1M1_20260120_1179.monitoring.h5

As ctapipe-process --monitoring-source, the monitoring source SST1MMonitoringSource fills the monitoring containers of each event with the monitoring data at its time, before its calibration:

  • the pointing of the telescope (event.monitoring.tel[tel_id].pointing), interpolated

  • the statistics of the ADC samples of the pedestal events (event.monitoring.tel[tel_id].camera.pixel_statistics.pedestal_waveform), used by the R0R1Calibrator for the voltage drop correction and the dead pixels (the outlier pixels of the monitoring are dead pixels)

  • the statistics of the images of the pedestal events (pixel_statistics.pedestal_image), used by the NSBImageCleaner

The statistics of an event are those of the last chunk of pedestal events ended before it: with the rolling chunks of sst1mpipe-monitoring, the statistics of the last 100 (ADC samples) and 1000 (images) pedestal events before the event, updated at each pedestal event. The events before the end of the first chunk use the first chunk. The events out of the time range of the chunks, by more than --SST1MMonitoringSource.timestamp_tolerance (1 s), or out of the pointing table, have no monitoring data and cannot be calibrated: they are skipped, and their number is given in the log. The pedestal events are calibrated and cleaned but not written: they are used to count the fraction of pedestal events which survive the cleaning.

Then the events are calibrated (R0R1Calibrator, CameraCalibrator, ImageSaturationCorrector), cleaned and parametrized (ImageProcessor), and their shower geometry is reconstructed (ShowerProcessor) if the DL2 is written (DataWriter.write_dl2, true in the data config).

The output file contains the DL1 (and DL2) of the events, /dl1/info (summary of the processing: calibration files, target, number of triggered and pedestal events, number of pedestal events which survive the cleaning, average fraction of pixels whose picture threshold is raised by the NSBImageCleaner) and, with --ProcessorTool.attach_monitoring=True (default), a copy of the monitoring data of the monitoring file (attach_monitoring_file). The DL1 file is then self-contained: e.g. load_dl1_sst1m reads the pointing of the events from it. The wobble of the run is added to the name of the output file (_W1, --ProcessorTool.wobble_in_output_name).

Other settings of the processing:

  • --ProcessorTool.allowed_sb_types: the runs processed, by type of scheduling block (OBSERVATION by default; UNKNOWN for the transitions between two wobbles, CALIBRATION for the dark and bias runs)

  • --max-events, --allowed-tels: events and telescopes processed

  • --DataWriter.write_dl1_images, --DataWriter.write_r1_waveforms: images and waveforms written

  • --progress: progress bar

Without monitoring source, the raw data are calibrated without the statistics of the pedestal events: no voltage drop correction, no dead pixels (only the bad_pixels and the pixels with bad calibration parameters), and the picture thresholds of the NSBImageCleaner are not raised. The output file has no pointing (the event source gives the RA/Dec of the run only), so it cannot be reconstructed in DL2 by sst1mpipe_dl1_dl2. This is used for the ZMQ streams of the real-time analysis (sst1mpipe_rta_config.json); a monitoring file can be given to the stream as well.

Simulations (.simtel.gz files) are processed without monitoring source, with the MC configuration files (sst1mpipe_mc_config_low_nsb.json, sst1mpipe_mc_config_high_nsb.json). How each telescope is calibrated is set in the configuration: for the simulated telescopes 1 and 2, the R1 waveforms of the simulation are kept and corrected for the PDE drop (R0R1Calibrator.calibrate_r0 false, pde_drop_factor), without saturation correction (ImageSaturationCorrector.apply_correction false):

sst1mpipe-process --input gamma.simtel.gz --output gamma.dl1.h5 \
    --config sst1mpipe/resources/config/sst1mpipe_mc_config_low_nsb.json

A night of data: the monitoring and the processing of each run, e.g.

CONFIG=sst1mpipe/resources/config
for raw in /data/raw/2026/01/20/SST1M1/SST1M1_20260120_*.fits.fz; do
    run=$(basename "$raw" .fits.fz)
    sst1mpipe-monitoring -i "$raw" -o "$run.monitoring.h5" --config $CONFIG/sst1mpipe_monitoring_config.json
    sst1mpipe-process -i "$raw" -o "$run.dl1.h5" --config $CONFIG/sst1mpipe_data_config.json \
        --monitoring-source SST1MMonitoringSource --SST1MMonitoringSource.input_files "$run.monitoring.h5"
done

The transition runs between two wobbles are skipped by sst1mpipe-process (no output events), and the dark runs have no pointing.

3. Merging

Monitoring data into a DL1 file: if the DL1 file was produced without the monitoring data (--ProcessorTool.attach_monitoring=False), they can be attached to it afterwards. The ctapipe monitoring data (pointing, statistics of the images) are attached by ctapipe-merge with the monitoring-only merge strategy, and attach_monitoring_file also attaches the statistics of the ADC samples (/r0/monitoring):

ctapipe-merge --append --merge-strategy monitoring-only \
    SST1M1_20260120_1179.monitoring.h5 --output SST1M1_20260120_1179_W1.dl1.h5

from sst1mpipe.io import attach_monitoring_file

attach_monitoring_file("SST1M1_20260120_1179.monitoring.h5", "SST1M1_20260120_1179_W1.dl1.h5")

DL1 files of several runs of a telescope (e.g. a night) are merged with ctapipe-merge (the files of the two telescopes have different subarrays: they are combined by the stereo step):

ctapipe-merge --input-dir dl1/ --pattern "SST1M1_20260120_*.dl1.h5" --output SST1M1_20260120.dl1.h5
# or
ctapipe-merge SST1M1_20260120_1179_W1.dl1.h5 SST1M1_20260120_1180_W1.dl1.h5 --output merged.dl1.h5

The events, the pointing tables, the statistics of the images of the pedestal events and the scheduling and observation blocks of the runs are merged. The statistics of the ADC samples (/r0/monitoring) and /dl1/info are not: they stay in the monitoring and DL1 files of the runs. --no-dl1-images merges the files without the images. The simulated DL1 files are merged in the same way (sst1mpipe_merge_hdf5 for a directory of MC files).

Reading the outputs

from ctapipe.io import HDF5EventSource, TableLoader
from sst1mpipe.io import load_dl1_sst1m, load_dl1_pedestals, load_r0_pedestals

# DL1 parameters with the pointing and the trigger time of the events
events = load_dl1_sst1m("SST1M1_20260120_1179_W1.dl1.h5", tel="tel_021")

# statistics of the pedestal events of the run
images = load_dl1_pedestals("SST1M1_20260120_1179_W1.dl1.h5", tel="tel_021")
samples = load_r0_pedestals("SST1M1_20260120_1179.monitoring.h5", tel="tel_021")

# ctapipe readers: the pointing of the events is interpolated from the pointing table
with TableLoader("SST1M1_20260120_1179_W1.dl1.h5") as loader:
    table = loader.read_telescope_events([21], dl1_parameters=True, pointing=True)

load_dl1_sst1m adds the parameters of the analysis which are not computed by ctapipe (add_dl1_extra_parameters): log_camera_frame_hillas_intensity, camera_frame_hillas_wl, equivalent_focal_length; for the observed data local_time, date and meanQ (mean charge of the pedestal images); for the simulations the true parameters of the showers, log_true_energy, the DISP parameters, miss and true_tel_impact_distance. They are not written in the DL1 files.
