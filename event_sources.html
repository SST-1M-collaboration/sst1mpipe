Event sources

The SST-1M data are read with two ctapipe event sources of sst1mpipe, registered as ctapipe I/O plugins: ctapipe.io.EventSource chooses the right one by itself from the input.

  • SST1MEventSource reads the raw data files (R0, SST1M<telescope>_<date>_<run>.fits.fz).

  • ZMQEventSource reads the events sent in a ZMQ stream, e.g. by the camera server for the real time analysis: DigiCam camera events (R0, as in the files) and CTAO R1 and DL0 events.

Both fill the R0 data of the DigiCam camera events in the same way: see the tutorial Reading SST-1M raw data (zfits) with the SST1MEventSource for what they contain.

from ctapipe.io import EventSource

with EventSource("SST1M2_20260120_1102.fits.fz", max_events=10) as source:
    for event in source:
        print(event.index.event_id, event.trigger.event_type)

SST1MEventSource

class sst1mpipe.io.sst1m_event_source.SST1MEventSource(input_url=traitlets.Undefined, config=None, parent=None, **kwargs)

Event source of the SST-1M raw data (R0) files.

The raw data are the zfits files SST1M<telescope>_<date>_<run>.fits.fz written by the DigiCam camera server: one file per run and telescope, with an Events table of DigiCam camera events (DataModel.CameraEvent protobuf messages). A single file is read.

SST1MEventSource is a ctapipe I/O plugin (entry point ctapipe_io): ctapipe.io.EventSource opens the SST-1M files with it by itself (see is_compatible).

For each camera event, it fills:

  • event.index: obs_id from the date and run number of the file name, and event_id, the SWAT array event id if the file has them (see swat_event_ids_available), the camera event number otherwise;

  • event.r0.tel[tel_id] (SST1MR0CameraContainer): the waveforms, DigiCam baselines and flags of the pixels in pixel id order, the camera event type and number, the event times, and the trigger traces in patch order (see fill_r0_event);

  • event.trigger: the time (White Rabbit, TAI), the telescope and the event type. The internal triggers of the camera are pedestal events of the type of the run (pedestal_event_type);

  • event.monitoring.pointing: the right ascension and declination of the pointing. The altitude and azimuth come from the monitoring data (SST1MMonitoringSource of sst1mpipe.io.monitoring_source).

The run information is read from the file: target, wobble and pointing from its TARGET field (target, wobble, pointing), start and duration from its header (scheduling_blocks, observation_blocks), and the configuration of the DigiCam boards (digicam_config). The subarray is the telescope of the file, from sst1m_array.h5.

The wrongly connected modules of a period (swapped_modules) are moved back, for the pixels and the trigger traces.

See also

sst1mpipe.io.zmq_event_source.ZMQEventSource

the same camera events, received in a ZMQ stream

Examples

>>> from ctapipe.io import EventSource
>>> with EventSource("SST1M2_20260120_1102.fits.fz", max_events=10) as source:
...     for event in source:
...         r0 = event.r0.tel[source.tel_id]
...         print(event.index.event_id, event.trigger.event_type, r0.waveform.shape)

property pointing_manual

True if the pointing is given by the user and not read from the file

property scheduling_blocks

property subarray

The telescope of the file, from sst1m_array.h5

swapped_pixels(tel_id, time)

Pixel ids of the wrongly connected modules (pairs) of the telescope tel_id at the time time, see swapped_modules

Target name from the TARGET field of the file

Wobble from the TARGET field of the file (W<n>, UNDEF or None)

ZMQEventSource

class sst1mpipe.io.zmq_event_source.ZMQEventSource(input_url=traitlets.Undefined, config=None, parent=None, **kwargs)

Event source of the telescope events sent in a ZMQ stream, e.g. by the camera server for the real time analysis.

The source connects a PULL socket to input_url (<transport>://<address>, e.g. tcp://192.168.1.1:1986) and reads the events until the end of the stream. It is a ctapipe I/O plugin (entry point ctapipe_io): ctapipe.io.EventSource opens a ZMQ endpoint with it (see is_compatible).

The messages of the stream (CTAMessage) are:

  • the DigiCam camera events (CAMERA_EVENT, DataModel.CameraEvent as in the zfits files), filling event.r0 and the trigger as the SST1MEventSource. The event id is the SWAT array event id if the first event has one, the camera event number otherwise.

  • the DigiCam run header (CAMERA_RUN_HEADER, DataModel.CameraRunHeader) of a telescope, available in run_headers, giving the obs_id of its camera events (see run_header_obs_id) if there is no data stream message.

  • the data stream of a telescope (TELESCOPE_DATA_STREAM, DL0_TELESCOPE_DATA_STREAM): its scheduling and observation blocks and the encoding of the waveforms (stored / waveform_scale - waveform_offset)

  • the camera configuration (CAMERA_CONFIG, DL0_TELESCOPE_CAMERA_CONFIG), available in camera_config

  • the events (R1_EVENT, DL0_TELESCOPE_EVENT), filling event.r1 or event.dl0, the event index and the trigger

  • END_OF_STREAM, which ends the reading.

The scheduling and observation blocks are only known once the data stream message is received; the type of the scheduling block is not sent and is scheduling_block_type. The type of the pedestal events (internal triggers of the camera events, generic PEDESTAL events of the R1/DL0 events) is not sent either and is pedestal_event_type.

A stream contains the data of a single telescope, and the subarray of the source is this telescope: allowed_tels if it gives a single telescope, otherwise the telescope of the first messages of the stream (received when the subarray is first used, and kept for the event loop).

See also

sst1mpipe.io.sst1m_event_source.SST1MEventSource

the camera events of the zfits files

Examples

>>> from ctapipe.io import EventSource
>>> with EventSource("tcp://192.168.1.1:1986") as source:
...     for event in source:
...         print(event.index.event_id, event.trigger.event_type, event.trigger.tels_with_trigger)
